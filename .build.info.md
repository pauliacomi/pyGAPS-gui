# Overview

This file contains details about how to perform a build of pygaps-gui (mostly
for me).

The GUI framework used for pyGAPS-GUI is Qt, more specifically its Python
bindings. The official Qt6 bindings are named PySide6 and are herein targeted.
An abstraction layer is used on top of PySide6, called QtPy. This is for ease of
documentation for anyone familiar with other Qt Python bindings.

The pyGAPS-GUI distribution is packed using PyInstaller.

Python 3.8 is no longer supported. CI checks installation and startup on Python
3.9 through 3.14 on Windows, Linux, and Apple Silicon macOS, plus Python 3.14 on
Intel macOS. Python 3.9 is retained for compatibility despite being end-of-life.
Release bundles are built with Python 3.14 and PySide6 on all platforms.

Create a Python 3.14 virtual environment and activate it:

    python -m venv ./.venv
    ./.venv/Scripts/activate

Install requirements:

    pip install --upgrade pip
    pip install -e .[build]

Check it all works

    pygapsgui
    # or
    python pyGAPS-gui.py

Run the test suite (pytest + pytest-qt; runs headless via Qt's offscreen platform)

    pip install -e .[test]
    python -m pytest

Regenerate the compiled Qt resources after changing `resources/resources.qrc`
or the icons it lists

    pyside6-rcc src/pygapsgui/resources/resources.qrc -o src/pygapsgui/widgets/resources_rc.py

Run pyinstaller

    python -m PyInstaller --noconfirm pyGAPS-gui.spec

This will generate the standalone frozen distribution in `./dist` Next step is
to collect it for the packaging. This is variable, per architecture.

## CI and releases

The GitHub Actions workflow uses pip (not conda). Every supported Python version
must pass dependency checks, the pytest suite, and startup checks before
standalone bundles are built. The suite drives the main window and analysis
dialogs headlessly (modal dialogs are auto-accepted). Both installed and frozen
applications run `--version` and `--test`; the latter reports exceptions to
stderr rather than opening a blocking dialog. CI uses Qt's offscreen platform.

All builds upload archives as workflow artifacts. Tag pushes publish the MSI,
Windows ZIP, Linux archive, and architecture-specific macOS ZIPs only after all
builds succeed. Linux bundles are built on Ubuntu 24.04 and require a compatible
glibc (they do not target older distributions). macOS bundles are unsigned.

## Windows installer

WiX 4 replaces WiX 3's `candle`/`light` commands. Install the .NET SDK specified
in `global.json`, then run from the repository root in PowerShell:

    $env:DOTNET_ROLL_FORWARD = "Major"
    dotnet tool restore
    $version = (Get-Content '.config\dotnet-tools.json' -Raw | ConvertFrom-Json).tools.wix.version
    dotnet tool run wix extension add "WixToolset.UI.wixext/$version"
    $folder = (Get-Item 'dist\pyGAPS-gui v*').FullName
    python ci\collect_dist.py msi zip "$folder"
    dotnet tool run wix build dist\pyGAPS-gui.wxs -arch x64 -ext WixToolset.UI.wixext -culture en-US -bindpath dist -out dist\pyGAPS-gui.msi
    Move-Item "$folder.zip" 'dist\pyGAPS-gui-win-x86_64.zip'

The local tool manifest pins WiX; the workflow installs the matching UI extension
using that version. WiX major upgrades are intentionally excluded from
Dependabot because later majors require a separate licensing/tooling review.
Runtime roll-forward lets WiX 4 use the maintained .NET SDK's runtime.
The PyInstaller bundle keeps a flat layout so installer resources remain in
their existing locations.
